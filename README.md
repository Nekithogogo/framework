# RackKeeper — система учета серверного оборудования

Приложение для учета серверов, установленного в них оборудования,
его характеристик и состояния. Консольная версия (ПР1–ПР3) дополнена
веб-интерфейсом на Django (ПР5), страницы которого формируются
шаблонами Django (ПР6).

## Используемые технологии

- Python 3.11;
- Django 5.2 — веб-фреймворк;
- Django Template Language (DTL) — шаблоны страниц;
- HTML5 — разметка веб-страниц;
- CSS3 и Bootstrap 5.3 — оформление страниц, собственные стили проекта;
- JavaScript — небольшое поведение интерфейса;
- JSON — хранение данных;
- pytest — автоматизированные тесты;
- flake8 — проверка качества кода.

## Назначение

RackKeeper помогает вести учет серверов и оборудования: какие комплектующие
стоят в каждом сервере, каковы их характеристики и в каком они состоянии.
Приложение отвечает на повседневные вопросы администратора: есть ли в
сервере свободный слот, можно ли установить в него новый модуль и какое
оборудование неисправно.

## Целевая аудитория

Системные администраторы и инженеры дата-центров и серверных комнат,
а также сотрудники, которые отвечают за закупку и списание оборудования.

## Предметная область

В серверной стоят серверы. У каждого сервера есть расположение (стойка)
и ограниченное число слотов под оборудование. В слоты устанавливается
оборудование: процессоры, модули памяти, диски, сетевые карты. У каждой
единицы оборудования есть характеристики (объем, частота, скорость и т. п.)
и текущее состояние: исправно, неисправно, в ремонте, списано.

## Основные сущности (классы)

Все классы находятся в пакете `models/`. Классы `Server`, `State` и
`Equipment` наследуют базовый класс `Entity` (идентификатор `id` и метод
`to_dict()`); хранилище сохраняет объекты любого из них одной функцией
`save_objects()` — это пример полиморфизма.

### Server — сервер (`models/servers.py`)

Атрибуты: `id`, `name`, `location`, `slots`.
Количество слотов инкапсулировано: свойство `slots` проверяет значение
при каждом изменении.

Методы:

- `is_suitable_for()` — у сервера не меньше заданного числа слотов;
- `get_free_slots()`, `get_load_percent()` — свободные слоты и загрузка;
- `get_load_level()` (`@staticmethod`) — словесная оценка загрузки;
- `validate_slots()` (`@staticmethod`) — проверка количества слотов;
- `from_data()` (`@classmethod`) — создание сервера из данных JSON;
- `__str__()` — строковое представление.

### State — состояние (`models/states.py`)

Атрибуты: `id`, `code`, `name`, `is_working` (можно ли устанавливать
оборудование в этом состоянии). Свойство `is_decommissioned` — признак
«списано». Методы `from_data()`, `to_dict()`, `__str__()`.

### Characteristic — характеристика (`models/characteristics.py`)

Атрибуты: `name`, `value`, `unit`. Своего идентификатора не имеет:
существует только в составе оборудования. `__str__()` возвращает строку
вида «Объем: 32 ГБ».

### Equipment — оборудование (`models/equipment.py`)

Атрибуты: `id`, `name`, `kind`, `serial_number`, `state` (объект `State`),
`server` (объект `Server` или `None`), `installed_at` (дата установки),
`characteristics` (список объектов `Characteristic`).

Методы:

- `is_installed` (свойство) — установлено ли оборудование в сервер;
- `needs_attention` (свойство) — неисправно или в ремонте (не списано);
- `can_be_installed()` — оборудование исправно и еще не установлено;
- `install()` / `uninstall()` — установка в сервер и снятие с него;
- `change_state()` — смена состояния (списанное снимается с сервера);
- `add_characteristic()`, `get_characteristic()` — работа с характеристиками;
- `to_dict()`, `__str__()`.

### Взаимодействие объектов

```
Equipment
├── state  ──→ State
├── server ──→ Server (или None — оборудование на складе)
└── characteristics ──→ [Characteristic, ...]
```

Оборудование обращается к связанным объектам напрямую:
`item.server.name`, `item.state.is_working`. Функции модулей работают
с коллекциями `List[Server]`, `List[State]`, `List[Equipment]`:
поиск, отбор, сортировка, подсчет занятых слотов, установка и снятие.

## Правила предметной области

- установить в сервер можно только исправное оборудование;
- установка возможна только при наличии свободного слота;
- одна единица оборудования установлена не более чем в один сервер;
- серийный номер оборудования уникален;
- списанное оборудование автоматически снимается с сервера.

## Возможности

- просмотр серверов с загрузкой, поиск, отбор по слотам, сортировка;
- добавление серверов;
- просмотр, поиск и добавление оборудования, просмотр оборудования сервера;
- добавление характеристик оборудованию;
- проверка возможности установки, установка и снятие оборудования;
- изменение состояния оборудования, просмотр справочника состояний;
- хранение данных между запусками в JSON-файлах.

## Хранение данных

На текущем этапе данные хранятся в JSON-файлах; Django ORM и база данных
приложения пока не используются, формы еще не реализованы.

- `data/servers.json` — серверы;
- `data/states.json` — справочник состояний;
- `data/equipment.json` — оборудование с характеристиками.

При загрузке данные JSON превращаются в объекты, при сохранении — обратно.
Связи оборудования хранятся идентификаторами `server_id` и `state_id`:

```json
{
    "id": 1,
    "name": "Intel Xeon Silver 4314",
    "kind": "CPU",
    "serial_number": "CPU-4314-0001",
    "server_id": 1,
    "installed_at": "2026-09-01",
    "state_id": 1,
    "characteristics": [{"name": "Ядра", "value": "16", "unit": "шт."}]
}
```

Если при загрузке сервер или состояние с указанным идентификатором
не найдены, запись пропускается с предупреждением.

## Веб-интерфейс

| URL | View-функция | Страница |
|-----|--------------|----------|
| `/` | `homepage.views.index()` | главная: описание и сводка по серверной |
| `/servers/` | `servers.views.servers()` | список серверов с загрузкой |
| `/servers/<int:server_id>/` | `servers.views.server_detail()` | сервер, свободные слоты, установленное оборудование |
| `/equipment/` | `equipment.views.equipment()` | таблица оборудования с состояниями |
| `/equipment/<int:equipment_id>/` | `equipment.views.equipment_detail()` | оборудование, характеристики, состояние |

Если сервер или оборудование с указанным идентификатором не найдены,
страница возвращает код 404. Для адресов без маршрута подключен
собственный обработчик `handler404` (`homepage.views.page_not_found()`),
он показывается при `DEBUG = False`.

Представления не формируют HTML в Python: они загружают объекты через
`storage.load_inventory()`, находят нужный объект (`find_server_by_id()`,
`find_equipment_by_id()`), готовят контекст и вызывают `render()`.
Функция `page()` из ПР5 удалена. Логика предметной области остается
в классах и функциях `models/` (`get_free_slots()`, `can_be_installed()`,
`needs_attention` и др.).

## Шаблоны Django

### Базовый шаблон и наследование

`templates/base.html` — общий каркас всех страниц: HTML-документ,
Bootstrap, собственный CSS, шапка с логотипом, навигация, подвал
и подключение JavaScript. Дочерние шаблоны наследуют его
(`{% extends "base.html" %}`) и переопределяют блоки
`{% block title %}` и `{% block content %}`.

### Включаемые шаблоны

| Шаблон | Что отображает | Где подключается |
|--------|----------------|------------------|
| `templates/includes/navigation.html` | навигация, активный раздел подсвечивается | `base.html` |
| `servers/includes/server_card.html` | карточка сервера со шкалой загрузки | список серверов, страница сервера |
| `equipment/includes/equipment_state.html` | бейдж состояния оборудования | главная, страница сервера, список и страница оборудования |

Параметры передаются через `with`:
`{% include "equipment/includes/equipment_state.html" with state=item.state %}`.

### Контекст, циклы и условия

Представления передают данные словарем контекста, например
`{"server_rows": [...]}` для списка серверов или `{"item": item}` для
страницы оборудования. Списки выводятся циклом `{% for %}` с веткой
`{% empty %}` для пустой коллекции. Условия `{% if %}` выбирают цвет
состояния (исправно / списано / неисправно), показывают «свободных слотов
нет», «на складе» и сообщение «не найдено» на страницах деталей
(в этом случае ответ имеет код 404).

### Именованные URL и пространства имен

У каждого приложения задан `app_name`; ссылки в шаблонах строятся только
через `{% url %}`:

- `homepage:index`;
- `servers:list`, `servers:detail`;
- `equipment:list`, `equipment:detail`.

### Фильтры шаблонов

Фильтры используются только для отображения данных:

- `|length` — количество серверов, оборудования, характеристик;
- `|default:"Без названия"` — значение по умолчанию;
- `|date:"d.m.Y"` — дата установки оборудования;
- `|yesno:"да,нет"` — можно ли установить оборудование;
- `|floatformat` — процент загрузки сервера;
- `|upper` — серийный номер.

### Статические файлы

Статика находится в `homepage/static/homepage/` и подключается в
`base.html` через `{% load static %}` и `{% static %}`:

- `css/style.css` — собственное оформление: шапка, карточки серверов,
  шкала загрузки, бейджи состояний, сводка на главной;
- `js/main.js` — текущий год в подвале и быстрый фильтр таблицы
  оборудования;
- `img/logo.png` — логотип в шапке.

## Операции веб-интерфейса

### Доступно в браузере

- просмотр списка серверов и их загрузки;
- просмотр сервера: слоты, загрузка, установленное оборудование;
- просмотр списка оборудования и его состояний;
- просмотр оборудования: характеристики, сервер, возможность установки.

### Отложено до следующих работ (работает в консольной версии)

Операции, изменяющие данные, появятся в веб-интерфейсе вместе с формами
и POST-запросами: добавление серверов и оборудования, характеристики,
поиск и отбор, установка и снятие оборудования, смена состояния.

Функции из ПР1 сохранены: логика `get_free_slots()`, `get_load_percent()` и
`get_load_level()` перешла в методы `Server`, а `can_install()` и
`get_install_status()` остались функциями модуля `models/equipment.py`.

Отдельное Django-приложение для пользователей не создавалось: Django уже
содержит модель `User` в `django.contrib.auth`, работа с пользователями
появится в теме аутентификации.

## Требования

- Python 3.11+;
- Django 5.2;
- pytest;
- flake8.

Установка зависимостей:

```
pip install -r requirements.txt
```

## Запуск

Веб-версия:

```
python manage.py migrate
python manage.py runserver
```

После запуска открыть http://127.0.0.1:8000/

Консольная версия (сохранена):

```
python main.py
```

## Запуск тестов

```
pytest -v
```

Тесты проверяют создание объектов и их атрибуты, методы классов,
взаимодействие объектов, правила установки, загрузку/сохранение JSON,
а также страницы Django-приложения и коды ответов 200/404.

## Проверка качества кода

```
flake8
```

Перед защитой также полезно выполнить `python manage.py check` и
`python manage.py findstatic homepage/img/logo.png`.

## План развития

- перенос сущностей в Django ORM и подключение базы данных;

- реализация пользователей;
- разработка API;
- контейнеризация приложения;
