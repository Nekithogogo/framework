# RackKeeper — система учета серверного оборудования

Консольное приложение для учета серверов, установленного в них
оборудования, его характеристик и состояния.

## Назначение

RackKeeper помогает вести учет серверов и оборудования: какие комплектующие
стоят в каждом сервере, каковы их характеристики и в каком они состоянии.
Приложение отвечает на повседневные вопросы администратора: есть ли в
сервере свободный слот, можно ли установить в него новый модуль и какое
оборудование неисправно.

## Целевая аудитория

Системные администраторы и инженеры дата-центров и серверных комнат,
а также сотрудники, которые отвечают за закупку и списание оборудования.

## Предметная область

В серверной стоят серверы. У каждого сервера есть расположение (стойка)
и ограниченное число слотов под оборудование. В слоты устанавливается
оборудование: процессоры, модули памяти, диски, сетевые карты. У каждой
единицы оборудования есть характеристики (объем, частота, скорость и т. п.)
и текущее состояние: исправно, неисправно, в ремонте, списано.

## Основные сущности (классы)

Все классы находятся в пакете `models/`. Классы `Server`, `State` и
`Equipment` наследуют базовый класс `Entity` (идентификатор `id` и метод
`to_dict()`); хранилище сохраняет объекты любого из них одной функцией
`save_objects()` — это пример полиморфизма.

### Server — сервер (`models/servers.py`)

Атрибуты: `id`, `name`, `location`, `slots`.
Количество слотов инкапсулировано: свойство `slots` проверяет значение
при каждом изменении.

Методы:

- `is_suitable_for()` — у сервера не меньше заданного числа слотов;
- `get_free_slots()`, `get_load_percent()` — свободные слоты и загрузка;
- `get_load_level()` (`@staticmethod`) — словесная оценка загрузки;
- `validate_slots()` (`@staticmethod`) — проверка количества слотов;
- `from_data()` (`@classmethod`) — создание сервера из данных JSON;
- `__str__()` — строковое представление.

### State — состояние (`models/states.py`)

Атрибуты: `id`, `code`, `name`, `is_working` (можно ли устанавливать
оборудование в этом состоянии). Свойство `is_decommissioned` — признак
«списано». Методы `from_data()`, `to_dict()`, `__str__()`.

### Characteristic — характеристика (`models/characteristics.py`)

Атрибуты: `name`, `value`, `unit`. Своего идентификатора не имеет:
существует только в составе оборудования. `__str__()` возвращает строку
вида «Объем: 32 ГБ».

### Equipment — оборудование (`models/equipment.py`)

Атрибуты: `id`, `name`, `kind`, `serial_number`, `state` (объект `State`),
`server` (объект `Server` или `None`), `installed_at` (дата установки),
`characteristics` (список объектов `Characteristic`).

Методы:

- `is_installed` (свойство) — установлено ли оборудование в сервер;
- `can_be_installed()` — оборудование исправно и еще не установлено;
- `install()` / `uninstall()` — установка в сервер и снятие с него;
- `change_state()` — смена состояния (списанное снимается с сервера);
- `add_characteristic()`, `get_characteristic()` — работа с характеристиками;
- `to_dict()`, `__str__()`.

### Взаимодействие объектов

```
Equipment
├── state  ──→ State
├── server ──→ Server (или None — оборудование на складе)
└── characteristics ──→ [Characteristic, ...]
```

Оборудование обращается к связанным объектам напрямую:
`item.server.name`, `item.state.is_working`. Функции модулей работают
с коллекциями `List[Server]`, `List[State]`, `List[Equipment]`:
поиск, отбор, сортировка, подсчет занятых слотов, установка и снятие.

## Правила предметной области

- установить в сервер можно только исправное оборудование;
- установка возможна только при наличии свободного слота;
- одна единица оборудования установлена не более чем в один сервер;
- серийный номер оборудования уникален;
- списанное оборудование автоматически снимается с сервера.

## Возможности

- просмотр серверов с загрузкой, поиск, отбор по слотам, сортировка;
- добавление серверов;
- просмотр, поиск и добавление оборудования, просмотр оборудования сервера;
- добавление характеристик оборудованию;
- проверка возможности установки, установка и снятие оборудования;
- изменение состояния оборудования, просмотр справочника состояний;
- хранение данных между запусками в JSON-файлах.

## Хранение данных

- `data/servers.json` — серверы;
- `data/states.json` — справочник состояний;
- `data/equipment.json` — оборудование с характеристиками.

При загрузке данные JSON превращаются в объекты, при сохранении — обратно.
Связи оборудования хранятся идентификаторами `server_id` и `state_id`:

```json
{
    "id": 1,
    "name": "Intel Xeon Silver 4314",
    "kind": "CPU",
    "serial_number": "CPU-4314-0001",
    "server_id": 1,
    "installed_at": "2026-09-01",
    "state_id": 1,
    "characteristics": [{"name": "Ядра", "value": "16", "unit": "шт."}]
}
```

Если при загрузке сервер или состояние с указанным идентификатором
не найдены, запись пропускается с предупреждением.

## Структура проекта

```text
server_inventory/
├── README.md
├── requirements.txt
├── main.py            — точка запуска, меню и сценарии
├── storage.py         — JSON ↔ объекты
├── utils.py           — безопасный ввод
├── models/
│   ├── __init__.py
│   ├── base.py        — базовый класс Entity
│   ├── servers.py     — Server и функции работы с серверами
│   ├── states.py      — State и функции справочника состояний
│   ├── characteristics.py — Characteristic
│   └── equipment.py   — Equipment и функции работы с оборудованием
├── data/
│   ├── servers.json
│   ├── states.json
│   └── equipment.json
└── tests/
    ├── test_servers.py
    ├── test_states.py
    ├── test_equipment.py
    └── test_storage.py
```

Функции из ПР1 сохранены: логика `get_free_slots()`, `get_load_percent()` и
`get_load_level()` перешла в методы `Server`, а `can_install()` и
`get_install_status()` остались функциями модуля `models/equipment.py`.

## Требования

- Python 3.11+;
- pytest;
- flake8.

Установка зависимостей:

```
pip install -r requirements.txt
```

## Запуск программы

```
python main.py
```

## Запуск тестов

```
pytest -v
```

Тесты проверяют создание объектов и их атрибуты, методы классов,
взаимодействие объектов, правила установки и загрузку/сохранение JSON.
